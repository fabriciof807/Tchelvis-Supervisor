# Chat Phase 1 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Replace the hand-rolled text editing with Herdr's native inputs in all 7 mod fields, and make the chat usable daily (autoscroll, focus, visible wait, markdown, starter questions, retry/edit, copy, open mentioned agents).

**Architecture:** Native `InputState`/`TextareaState` objects are created once in `init` and read with `value()`; the mod keeps no draft copies. Chat view uses a `ScrollHandle`; new behaviour that can be pure (agent mentions, starter list, clipboard argv, elapsed label) lives in exported helpers tested in Node.

**Tech Stack:** Herdr Desktop mod JS (`gpui-kit`, `gpui-base`, `herdr`), Node tests with `tests/mod/stub-hooks.mjs`.

**Spec:** `docs/superpowers/specs/2026-11-18-chat-phase1-design.md` (API facts there come from the user's host `gpui-kit.d.ts`; trust them over guesses).

## Global Constraints

- Only `assets/herdr-app/mods/tchelvis/main.js`, `tests/mod/*.test.mjs` and `tests/mod/stub-hooks.mjs` change. No Rust changes.
- Native states are created in `init` (never in `render`): `InputState.new({placeholder, value})`, `TextareaState.new({placeholder, value, rows})`; rendered with `Input.new(state)` / `Textarea.new(state)` and styled by the mod (height, padding, rounded, border colour from theme, `t.accent` border while focused via `focus`/`blur` events). Read with `state.value()`, clear with `state.set_value("")`.
- Named imports `InputState, Input, TextareaState, Textarea` from `"gpui-base"` (proven by Herdr's shipped mods). `ScrollHandle` and `TextView` are read through `import * as base from "gpui-base"` and used only if defined (fallback: no autoscroll / plain text).
- Multiline (`TextareaState`, `set_auto_grow(1, 6)`): `chat`, `task`. Single line (`InputState`): `fallbackHost`, `modelFilter`, `command`, `prompt`, `label`.
- Submit: each field's existing submit action runs on its state's `submit` event and on its existing button. Escape still leaves editing (view-level `handleKeyDown` keeps only Escape and non-text shortcuts).
- Remove: `applyTextKey`, `textWithCaret`, `TEXT_FIELDS`, `MULTILINE_FIELDS`, the caret `▏` rendering, `this.caret`, the per-field draft properties (`taskDraft`, `chatDraft`, `fallbackHostDraft`, `modelFilterText`, `commandDraft`, `promptText`, `labelValue`) and `tests/mod/text-edit.test.mjs` (the code it tests is deleted). Keep `isBlankDraft`.
- Chat timing: elapsed counter via `cx.timer.every(1000, …)` only while a request is pending; cancel it when the request ends.
- Clipboard: `exec` has no stdin, so the text goes as an argv item to a fixed script (see `clipboardArgv` in Task 3); never interpolate it into the shell string.
- Strings in Portuguese; theme colours only.

## Review Focus

- Herdr reload / layout switch re-runs `init`: states are recreated empty; history (`chatMessages`) is in memory and may reset — accepted (spec).
- A field submitted while blank → nothing happens (use `isBlankDraft(state.value())`).
- Agent mention false positives: an address like `t1` inside `t10` must not match; match whole tokens only. Test in Task 3.
- Clipboard text containing quotes/newlines/`$` → passed as one argv item, never interpolated into the shell string. Test in Task 3.
- `TextView`/`ScrollHandle` missing at runtime → mod still loads and renders plain text without autoscroll. Test in Task 2 (stub without them).

**Interfaces (exports):**
- `chatElapsedLabel(startedAtMs, nowMs)` → `"◌ Gerando… 6s"` (`Math.floor` seconds; `< 1 s` → `"◌ Gerando…"`).
- Behaviour: `this.chatScroll = base.ScrollHandle?.new?.() ?? null` in `init`; the messages list gets `.track_scroll(this.chatScroll)` when non-null; after pushing the user message, after the answer/error arrives, and when the chat tab opens, call `this.chatScroll?.scroll_to_item(lastIndex)` (last rendered child, including the pending row). Assistant text uses `base.TextView?.markdown?.(\`ck-chat-md-${i}\`, content)` when available, else the current plain text.

### Task 3: Chat actions — starters, retry/edit, copy, open agent

**Files:**
- Modify: `assets/herdr-app/mods/tchelvis/main.js` (`renderChatBody`, `sendChatMessage`; reuse `focusOrAttachTerminal` and the Fleet rows from `mergeFleetRows(agents(), terminals(), shared("cockpit.snapshot"), shared("supervisor.snapshot"))`)
- Create: `tests/mod/chat-actions.test.mjs`

**Interfaces (exports):**
- `export const CHAT_STARTERS = ["Quem está esperando por mim?", "Quais tarefas estão abertas?", "Resumo dos agentes", "O que faço primeiro?"]`.
- `extractMentionedAgents(text, rows)` → rows whose `address` or `name`/`term_name` appears in `text` as a whole token (case-insensitive; boundaries = start/end or a non `[A-Za-z0-9_-]` char); unique, in order of first appearance, at most 4.
- `clipboardArgv(text)` → `["sh", "-c", 'printf %s "$1" | (wl-copy 2>/dev/null || xclip -selection clipboard 2>/dev/null || xsel --clipboard --input)', "sh", text]`.
- `sendChatMessage(cx, presetQuestion = null)`: uses `presetQuestion` when given (starters, retry) instead of the input value; error entries keep `prompt: question`.
- UI: empty chat shows the 4 starters as buttons (click → `sendChatMessage(cx, q)`); error entries show `↻ Tentar de novo` (`sendChatMessage(cx, m.prompt)`) and `Editar` (`this.inputs.chat.set_value(m.prompt)`; `focusField("chat")`); assistant entries show `Copiar` (`exec(...clipboardArgv(m.content))` → label `Copiado` for 2 s) and one `↗ Abrir <name>` button per mentioned agent (→ the same call the Fleet row click uses for that row).

- [ ] **Step 1: Write the failing tests** in `chat-actions.test.mjs`:

  - `mentions are unique and capped at 4`.
  - `clipboard argv keeps the text as one argument` — text `'a "b" $HOME\nc'` → last item equals it exactly, and the `-c` script does not contain it.
- [ ] **Step 2: Run** `node --import ./tests/mod/stub-hooks.mjs --test tests/mod/chat-actions.test.mjs` — Expected: FAIL.
