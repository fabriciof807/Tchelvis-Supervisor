## What this proposes
Cockpit proposes a local-first, read-only dashboard and CLI suite for monitoring coding agents running inside Herdr (`herdr-core` / `hc`), consisting of a single-instance Rust daemon/CLI (`cockpit`) and a stateless native Herdr Desktop (`herdr-app`) mod rendered via `gpui-kit`. Low-latency (`<20 ms`) shell and agent hooks emit OSC 7501 status sequences and attach `hc` terminal provenance labels, while the daemon consumes `hc` events, inspects local git workspace state, and runs event-gated, deduplicated, quota-guarded queries across read-only `ContextProvider` adapters (GitHub, GitLab, Jira, Linear, Slack, and local Markdown runbooks). Pre-computed `CockpitSnapshot` projections are cached locally in SQLite WAL and published over a Unix domain socket, `hc`'s `doc.set` store, and CLI commands (`status`, `watch`, `inspect`, `doctor`), pinning blocked agents at the top of an attention queue with deterministic correlation tiers (`Exact`, `Inferred`, `Ambiguous`, `LocalOnly`). A reversible `cockpit setup` / `cockpit uninstall` engine manages hook scripts, config merges, and Herdr mod assets using an explicit rollback manifest.

## How the existing system works, per this document
Per this document, coding agents (such as Claude Code, OpenCode, and Pi) and interactive shells run inside PTY terminals managed by `herdr-core` (`hc 0.1.20`), which tracks terminal lifecycles (`live` / `finished`), `OSC 7501` status updates (`idle`, `working`, `done`, `blocked`, `error`), terminal labels (`hc label`), and terminal listing/event streams (`hc ls --all --json`, `hc events --json`, and `hc connect` OpenRPC). `herdr-core` also provides a built-in document store (`doc.set`) that pushes automatic `doc` events to the `herdr-app` desktop UI, which supports native `gpui-kit` JavaScript mods and switchable layouts. Currently, agents inside Herdr may lack consistent `OSC 7501` hooks and provenance labels, and external context (GitHub `gh` / GitLab `glab` PRs, CI checks, deploys, Jira/Linear tickets, Slack threads, and local runbooks) remains fragmented across disconnected CLI tools and APIs that share local user tokens and rate-limit quotas.
